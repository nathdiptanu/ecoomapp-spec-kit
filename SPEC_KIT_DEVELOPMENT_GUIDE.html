Spec-Kit Development Guide For SpecShop

This guide explains how to install Python, set up this Flask ecommerce project, install Spec-Kit, and use Spec-Kit prompts to develop new features from requirements through implementation.

Official Links

  • Spec-Kit installation
  • Spec-Kit quick start

1. Install Python On Windows

  1. Download Python 3.11.1 from python.org.
  2. Run the installer.
  3. Select Add python.exe to PATH.
  4. Select Customize installation.
  5. Keep pip selected.
  6. Finish installation, then restart VS Code and PowerShell.
python --version
pip --version
py -0p

If Python is still not found, open Windows Settings, go to Apps > Advanced app settings > App execution aliases, turn off python.exe and python3.exe, then reinstall Python with PATH enabled.

2. Open The Project In VS Code

cd C:\Users\MSUSERSL123\Documents\SpecDrivenDevelopment
code .

Install the Python, GitHub Copilot, and GitHub Copilot Chat extensions.

3. Create The Virtual Environment

python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt

If activation is blocked:

Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
.\.venv\Scripts\Activate.ps1

Run the app:

python run.py

Open http://127.0.0.1:5000.

Run tests:

pytest

4. Install Spec-Kit

Install Spec-Kit from the official GitHub repository.

powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

Restart the terminal, then:

uv --version
uv tool install specify-cli --from git+https://github.com/github/spec-kit.git
specify version
specify self check

Initialize this project:

cd C:\Users\MSUSERSL123\Documents\SpecDrivenDevelopment
specify init . --script ps --integration copilot

5. Recommended Workflow

Quick experiment path:

/speckit.specify -> /speckit.plan -> /speckit.tasks -> /speckit.implement

Full feature path:

/speckit.constitution -> /speckit.specify -> /speckit.clarify -> /speckit.checklist -> /speckit.plan -> /speckit.tasks -> /speckit.analyze -> /speckit.implement

6. Prompt Meanings

/speckit.constitution

Defines project principles and guardrails.

/speckit.constitution This is a Flask ecommerce learning project. Use Python 3.11, Flask, SQLAlchemy, SQLite, Jinja2, Bootstrap 5, and pytest. Keep requirements in local markdown files. Avoid real payment processing in v1. Every feature should include tests for the main workflow.

/speckit.specify

Creates the feature specification. Focus on what users need and why.

/speckit.specify Add product reviews. Shoppers can submit a reviewer name, rating from 1 to 5, and comment from the product detail page. Product pages display reviews and average rating. Authentication is not required.

/speckit.clarify

Finds and resolves ambiguous requirements before planning.

/speckit.clarify Focus on review validation, rating rules, anonymous users, and whether reviews can be edited or deleted.

/speckit.checklist

Validates that the specification is complete enough to plan.

/speckit.checklist

/speckit.plan

Creates the technical plan. Put stack, architecture, database, UI, and testing choices here.

/speckit.plan Use Flask, SQLAlchemy, SQLite, Jinja2 templates, Bootstrap 5, and pytest. Add a Review model related to Product. Add a POST route for review creation. Update the product detail page and add tests.

/speckit.tasks

Breaks the plan into ordered implementation tasks.

/speckit.tasks

/speckit.analyze

Checks consistency between spec, plan, and tasks before coding.

/speckit.analyze

/speckit.implement

Executes the tasks and writes code.

/speckit.implement

7. Sample Feature Prompts

Product Reviews

/speckit.specify Add product reviews to the ecommerce app. Shoppers can add a review to a product detail page with reviewer name, rating from 1 to 5, and comment. Product detail pages show all reviews and average rating. Authentication is not required. Reviews should be stored in SQLite. Reviews cannot be edited or deleted in this version.

Wishlist

/speckit.specify Add a wishlist feature. Shoppers can add products to a wishlist from catalog and product detail pages. The wishlist is stored in the session for v1. Shoppers can view wishlist items, remove items, and move an item from wishlist to cart. Authentication is not required.

Catalog Pagination

/speckit.specify Improve the product catalog with pagination. The catalog should show 12 products per page, preserve search and category filters between pages, and display previous/next controls. The UI should remain responsive.

Admin Authentication

/speckit.specify Add simple admin authentication. Admin pages should require login. A single admin username and password can be configured with environment variables. Shopper catalog, cart, and checkout remain public.
